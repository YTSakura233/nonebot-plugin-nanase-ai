# 方案设计

## 2026-11-01

独立目录包含自己的pyproject.toml、包、环境示例、来源说明、测试与文档。父项目运行代码不改动。Python 3.11+，NoneBot2/OneBot V11，Pydantic配置，aiomysql持久化，HTTPX调用DeepSeek，MCP SDK 2.x可选，PDF/Word解析可选。

流程：OneBot事件→规范化Message/Update→白名单和成员准入→命令或媒体处理→写聊天记录→三秒聚合→会话锁→相关记忆与知识库候选→Flash策略JSON→Flash/Pro正文及受限工具循环→闲聊合宜性/重复审查→QQ分段发送→仅保存实际发送结果和对应状态。

数据：soruto_nb_users、ai、chat_context、chat_summary、memory_facts、media_description、knowledge共七表。chat_id为“机器人:聊天类型:目标”字符串，避免群/私聊/机器人号碰撞。个人好感度与个人事实按QQ共享。压缩摘要与删除原文同事务；重置仅当前会话。

模型：Flash日常、策略、摘要及视觉；Pro复杂问答；原图请求强制视觉链。正式回复不强制JSON。工具执行前仅基础设施故障允许备用模型，执行后不重放。reasoning_content只用于本轮API续传。

工具：DeepSeek Search/Fetch；MCP按服务allowed_tools过滤，再按用户/群筛选，闲聊只读且必须额外点名。SDK连接由专属任务拥有，避免AnyIO退出上下文跨任务。Skills按启用目录读取SKILL.md/引用，所有路径解析后验证，不执行脚本。没有工具的回合不注入技能。

知识库：启动或CLI导入Markdown/TXT/PDF/DOCX，事务替换来源片段；BM25中英文召回，可选DeepSeek扩展同义词，最终策略选择，标注文件来源。不是向量索引。规模与单文件设上限，解析在线程执行。

运行边界：模型并发、排队回合、Agent步数、工具次数/时间有界；错误日志只输出类型和HTTP状态，避免原始聊天和凭据。退出时先取消生成，再关MCP、HTTP和数据库池。

实现顺序：数据/配置/事件适配→原决策与记忆移植→直接API与工具→知识库和Skills→离线验证与修复→构建与安装包检查。需求由会话逐项确认；此文归档最终实现设计。
